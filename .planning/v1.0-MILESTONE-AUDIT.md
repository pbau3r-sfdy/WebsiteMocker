## Blocker

### COLLAB-05 — content-sync.yml Not Deployed

**Requirement:** `content-ci.yml` in each production repo dispatches WebsiteMocker's `content-sync.yml` when `content/**/*.md` files change on `main`.

**Status:** PARTIAL / BLOCKER

**Root cause:** Local `main` branch is **32 commits ahead of `origin/main`**. The `.github/workflows/content-sync.yml` workflow exists in the local working tree and is fully implemented (correct event type, additive sync logic, security controls, YAML validates clean), but it has never been pushed to `pbau3r-sfdy/WebsiteMocker`.

**Impact:** A contributor pushing `.md` to any production repo today triggers `content-ci.yml`, which fires `repository_dispatch(content-updated)` to `pbau3r-sfdy/WebsiteMocker`. The remote WebsiteMocker repo has no handler for this event — the dispatch silently disappears. No content sync occurs. No operator alert is generated.

**Fix (one command):**
```bash
git push origin main
```

This single command resolves the blocker. No code changes required.

## Warnings (Tech Debt — Non-Blocking)

### Warning 1: wm-ingest.md Notes contradicts auto-injection

**File:** `.claude/skills/wm-ingest.md` line 102

**Current text:**
> "Google Fonts `<link>` tags are not converted — they are printed as instructions to add to `Layout.astro <head>`"

**Reality:** `ingest-artifact.mjs` line 636 auto-injects Google Fonts `<link>` tags into `Layout.astro` before `</head>`. An operator following the Notes would add them manually, creating duplicate `<link>` tags. The idempotency guard (`fonts.googleapis.com` already present check) would catch a second script run, but the Notes are wrong.

**Fix:** Update Notes line 102 to say auto-injection occurs.

### Warning 2: wm-ingest.md Step 7 missing /wm-publish handoff

**File:** `.claude/skills/wm-ingest.md` Step 7

**Issue:** The operator flow ends at `node _scripts/build-all.js <slug>`. No instruction to run `/wm-publish <slug>` to go live. First-time operators have no path from "ingest complete" to "site is live."

**Fix:** Add a "Next: push to production" pointer at the end of Step 7.
