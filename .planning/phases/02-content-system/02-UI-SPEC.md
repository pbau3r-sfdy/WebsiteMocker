# Phase 2 — UI Design Contract: Content System

> Visual and interaction contract for the four content type page templates (news, jobs,
> announcements, blog). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Context and Scope

This phase creates new Astro page templates and card components for three content types that do
not yet exist (jobs, announcements, blog) and migrates the existing news templates from Astro 4
to Astro 5. All templates target three active multi-tenant sites:

- `sfdy-alt-clean` (Starflight Dynamics) — dark theme, Avenir Next + IBM Plex Mono fonts
- `mogwai-systems` (MOGWAI) — holding page, brand TBD
- `parrot-capital` (Parrot Capital UG) — holding page, brand TBD

**Multi-tenant constraint:** Templates MUST NOT hard-code brand colours or fonts. All colour
and typography values are referenced via CSS custom properties (e.g. `var(--accent)`,
`var(--surface-1)`) that each site defines in its own `Layout.astro`. The UI-SPEC defines the
token contract — each site populates the tokens with its brand values.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage in templates |
|-------|-------|--------------------|
| xs | 4px | Icon gaps, tag pill internal padding |
| sm | 8px | Compact gaps (gap between tag pills) |
| md | 16px | Card body padding, list item internal gap |
| lg | 24px | List wrapper top padding, info column gap |
| xl | 32px | Blockquote/body section margin |
| 2xl | 48px | Header bottom padding |
| 3xl | 64px | Not used directly — see exceptions |

Exceptions (inherited from existing news system — do not change):

| Value | Where used | Rationale |
|-------|-----------|-----------|
| 12px | Announcement row internal gap (`flex-direction: column; gap: 12px`) | Tighter than md(16px) for visual density of multi-field rows |
| 36px | Row padding-top/bottom in list pages; header padding-bottom in detail | Midpoint between xl and 2xl; established pattern |
| 44px | `margin-bottom` on back navigation link in detail pages | Established pattern from news detail |
| 72px | `main` top padding (list and detail pages) | Established sfdy-alt-clean convention; gives clearance below fixed Nav |
| 120px | `main` bottom padding | Generous breathing room above footer; established pattern |

Source: Measured from `sites/sfdy-alt-clean/src/pages/news/index.astro` and `[slug].astro`.

## Typography

All sizes are declared for `_core` template use. Sites may override via their CSS but must
preserve the weight and line-height ratios for readability.

Exactly 4 sizes, exactly 2 weights (300 and 700). The heading size doubles as card title and
body long-form size — weight and line-height vary by context, size is shared.

| Role | Size | Weight | Line Height | Font stack |
|------|------|--------|-------------|-----------|
| Display | `clamp(2.4rem, 6vw, 5rem)` | 700 | 1.1 | `var(--font-display)` |
| Subheading (article h1) | `clamp(1.75rem, 4vw, 2.75rem)` | 700 | 1.14 | `var(--font-display)` |
| Heading / card title / body | `clamp(1.0625rem, 2vw, 1.5rem)` | 700 (headings, card titles) · 300 (body text) | 1.24 (headings) · 1.55 (body) | `var(--font-display)` (headings/card titles) · `var(--font-body)` (body) |
| Label / eyebrow | `11px` | 300 | n/a | `var(--font-mono)`, uppercase, `letter-spacing: var(--ls-eyebrow)` — visual distinction is carried by uppercase + `.34em` letter-spacing, not weight |

Source: Measured from existing `Layout.astro` global styles and news page templates.
No new type sizes are introduced — all new templates reuse these declared sizes.

### New (to be created in `_core/src/`)

#### TagPill component (`components/TagPill.astro`)

Anatomy:
```
<span class="tag">{ tag }</span>
```
- Display: `inline-block`
- Padding: 4px 8px (xs sm)
- Border: `1px solid var(--border-subtle)`
- Font: 11px, weight 300, uppercase, `var(--font-mono)`, letter-spacing 0.12em
- Text colour: `var(--accent)`
- Background: transparent
- Gap between pills: 8px (sm)
- No hover state (informational only)

#### TypeBadge component (`components/TypeBadge.astro`)

Used on job cards and detail pages only.
Maps `type` field to display label:
- `full-time` → `FULL-TIME`
- `part-time` → `PART-TIME`
- `contract` → `CONTRACT`

Anatomy: Same style as TagPill. Border colour: `var(--border-strong)` (not subtle) to
distinguish from content tags.

#### JobCard component (`components/JobCard.astro`)

List row layout (matches existing news row pattern):

```
<a href="/jobs/{id}" class="row">
  <div class="meta">
    <span class="mono date">{ date }</span>          ← accent colour
    <TypeBadge type={type} />
  </div>
  <div class="info">
    <h2>{ title }</h2>
    <p class="dept-loc">{ department } · { location }</p>
  </div>
</a>
```

- No thumbnail column (jobs have no image field)
- Row: `display: grid; grid-template-columns: 180px 1fr; gap: 24px`
- Row padding: 36px 0
- Row border-bottom: `1px solid var(--border-subtle)`
- Row hover: `background: rgba(255,255,255,.04)`
- Department + location: `clamp(1.0625rem, 2vw, 1.5rem)`, weight 300, `var(--text-soft)`, single line

Closed jobs: rendered only when filtering is disabled. Visual treatment: `opacity: 0.45` and
`pointer-events: none` on the row. Not included in the default list (open-only per CONTENT-06).

#### AnnouncementCard component (`components/AnnouncementCard.astro`)

List row layout (no image, tag pills):

```
<a href="/announcements/{id}" class="row">
  <div class="info">
    <span class="mono date">{ date }</span>
    <h2>{ title }</h2>
    <p>{ summary }</p>
    <div class="tags">{ tags.map(t => <TagPill tag={t} />) }</div>
  </div>
</a>
```

- Single full-width column (no thumbnail)
- Row: `display: flex; flex-direction: column; gap: 12px` (see Spacing exceptions — 12px)
- Row padding: 36px 0
- Row border-bottom: `1px solid var(--border-subtle)`
- Row hover: `background: rgba(255,255,255,.04)` with 8px left padding transition

#### BlogCard component (`components/BlogCard.astro`)

Card grid layout (matches existing NewsCard grid style):

```
<a href="/blog/{id}" class="card">
  <div class="thumb">{ image or placeholder }</div>
  <div class="body">
    <span class="mono date">{ date }</span>
    <h3>{ title }</h3>
    <p class="author">{ author }</p>
  </div>
</a>
```

Identical visual treatment to `NewsCard` with addition of `author` line:
- Author: 11px, weight 300, `var(--text-muted)`, `var(--font-mono)`, no uppercase

## Page Layouts

**Primary focal point: h1 page title** — the largest text element on every list and detail page.
All other elements (eyebrow, summary, cards) are visually subordinate to it.

### List pages — all four types

```
<Layout title="{Type}" description="...">
  <Nav />
  <main>
    <header>                                       ← padding: 72px var(--gutter) 48px
      <div class="wrap head">
        <div class="eyebrow">{ SECTION LABEL }</div>
        <h1>{ Page Title }</h1>
      </div>
    </header>
    <div class="list">                             ← max-width: 1000px; margin: 0 auto
      { entries.map(entry => <Card ... />) }
      { entries.length === 0 && <EmptyState /> }
    </div>
  </main>
  <Footer />
</Layout>
```

Section labels (eyebrow text, all-caps):
- news: `NEWSROOM`
- jobs: `CAREERS`
- announcements: `ANNOUNCEMENTS`
- blog: `BLOG`

Page titles:
- news: `News & announcements` (& in accent colour)
- jobs: `Open positions`
- announcements: `Announcements`
- blog: `Blog`

Blog list uses a CSS grid (same as the card component in NewsCard pattern):
```css
.grid { display: grid; grid-template-columns: repeat(auto-fill, minmax(280px, 1fr)); gap: 24px; padding: 24px var(--gutter) 120px; }
```

News, jobs, announcements lists use row layout:
```css
.list { max-width: 1000px; margin: 0 auto; padding: 24px var(--gutter) 120px; }
```

Breakpoint: `@media (max-width: 680px)` — news row collapses thumbnail column to full-width
stack; jobs row collapses meta column to above info. All other list types already single-column.

### Detail pages — all four types

```
<Layout title={entry.data.title} description={entry.data.summary}>
  <Nav />
  <main>                                           ← padding: 72px var(--gutter) 120px
    <article>                                      ← max-width: 760px; margin: 0 auto
      <a href="/{type}" class="back mono">← All {type}</a>
      <header>
        <span class="mono date">{ date }</span>
        { type-specific metadata line }
        <h1>{ title }</h1>
        <p class="summary">{ summary }</p>
        { tags && <div class="tags">{ tags.map(t => <TagPill tag={t} />) }</div> }
      </header>
      { image && <img class="lead" src={image} alt="" /> }
      <div class="body"><Content /></div>          ← rendered Markdown
    </article>
  </main>
  <Footer />
</Layout>
```

Type-specific metadata line in detail header:
- jobs: `<TypeBadge type={type} /> · { location }`
- blog: `By { author }` (if author present), 11px mono
- news: none (date is sufficient)
- announcements: none

Back link text:
- news: `← All news`
- jobs: `← All positions`
- announcements: `← All announcements`
- blog: `← All posts`

## Interaction Patterns

### Jobs list: open/closed filter

- Default state: show open jobs only (`open: true`)
- No interactive filter toggle is required for this phase (static build)
- Closed jobs are excluded at `getCollection` query level via `.filter(j => j.data.open !== false)`
- No pagination required (static build, all entries rendered)

### Card hover state (all types)

Row-based cards (news list, jobs, announcements):
- `border-bottom` colour transitions from `var(--border-subtle)` to `var(--border-accent)` — duration: 200ms, easing: `cubic-bezier(.2,.6,.2,1)`
- Background shifts to `rgba(255,255,255,.04)` on hover
- No translate animation on rows (translate reserved for grid cards only)

Grid cards (blog, NewsCard):
- Border transitions from `var(--border-subtle)` to `var(--border-accent)` — same timing
- `transform: translateY(-2px)` on hover — same timing

### Back navigation

- Always a plain `<a>` rendered with `.back.mono` classes
- Colour: `var(--text-muted)` at rest
- Hover: `var(--accent)` (inherited from `Layout.astro` global `a:hover`)
- No JavaScript — standard anchor tag

## Accessibility Requirements

| Requirement | Implementation |
|------------|---------------|
| Semantic structure | `<main>`, `<header>`, `<article>`, `<nav>` — as in existing news templates |
| Image alt text | Decorative lead images: `alt=""`. Thumbnail images in cards: `alt=""`. Author images (not in scope): `alt="{name}"` |
| Date format | Machine-readable: `<time datetime="YYYY-MM-DD">` wrapping the mono date span |
| Keyboard navigation | All cards are `<a>` elements — no `div`+`onClick`. Tab order follows DOM order |
| Focus ring | Browser default — do not suppress `outline`. Existing `Layout.astro` does not suppress it |
| Language | `lang="en"` on `<html>` — already set in Layout.astro |
| Min touch target | Card rows span full width — no minimum size concern. Back link: ensure `padding: 8px 0` for touch comfort |

**`<time>` element contract (new requirement, not in existing news templates):**

```html
<time class="mono date" datetime={entry.data.date.toISOString().split('T')[0]}>
  {stamp}
</time>
```

Apply to ALL new templates. Retrofit to news templates during migration.

## Copywriting Contract

### Per content type

| Element | Jobs | Announcements | Blog |
|---------|------|--------------|------|
| Section eyebrow | `CAREERS` | `ANNOUNCEMENTS` | `BLOG` |
| Page h1 | `Open positions` | `Announcements` | `Blog` |
| Empty state heading | `No open positions` | `No announcements yet` | `No posts yet` |
| Empty state body | `We're not hiring right now. Follow us for updates.` | `Nothing to announce at this time.` | `Articles will appear here when published.` |
| Back link text | `← All positions` | `← All announcements` | `← All posts` |
| CTA (card link — accessible label via aria) | `View position: {title}` | `Read announcement: {title}` | `Read post: {title}` |

### News (existing — confirm no change)

| Element | Copy |
|---------|------|
| Section eyebrow | `NEWSROOM` (existing) |
| Back link text | `← All news` (existing) |
| Empty state | Not needed (sfdy-alt-clean has 6 articles; mogwai and parrot-capital will be scaffolded with at least `.gitkeep` — empty dirs will not be reached in the list page if content dirs are empty and getCollection returns []) |

Note: Empty state for news is handled by rendering zero `<a class="row">` elements. Add an
explicit empty state block for correctness, even if unlikely to appear:
`No news articles yet.`

### Destructive actions

None. This phase is read-only at render time. Content creation is performed by skills
(`/wm-add-*`) that operate via the operator's terminal and git. No in-browser destructive
action is possible.
