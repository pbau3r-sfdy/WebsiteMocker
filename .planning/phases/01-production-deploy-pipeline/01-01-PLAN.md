Step 4 — Validate wiring.json (DEPLOY-02: must run BEFORE build, exits non-zero on failure):
```yaml
- name: Read and validate wiring.json
  id: wiring
  run: |
    node -e "
      const fs = require('fs');
      const slug = process.env.SLUG;
      if (!/^[a-z0-9-]+$/.test(slug)) {
        console.error('Error: slug must match ^[a-z0-9-]+$');
        process.exit(1);
      }
      const path = 'sites/' + slug + '/wiring.json';
      let w;
      try { w = JSON.parse(fs.readFileSync(path, 'utf-8')); }
      catch(e) { console.error('Error: cannot read ' + path); process.exit(1); }
      if (w.stage < 5)   { console.error('Error: stage ' + w.stage + ' < 5 — site not production-ready'); process.exit(1); }
      if (!w.domain)     { console.error('Error: domain missing in wiring.json'); process.exit(1); }
      if (!w.prod_repo)  { console.error('Error: prod_repo missing in wiring.json'); process.exit(1); }
      const out = 'domain=' + w.domain + '\nprod_repo=' + w.prod_repo;
      fs.appendFileSync(process.env.GITHUB_OUTPUT, out + '\n');
      console.log('Validated: stage=' + w.stage + ' domain=' + w.domain + ' prod_repo=' + w.prod_repo);
    "
  env:
    SLUG: ${{ inputs.slug }}
```

Step 5 — Build single site (DEPLOY-06, with DEPLOY-01 prod env vars):
```yaml
- name: Build site
  run: node _scripts/build-single.mjs ${{ inputs.slug }}
  env:
    SITE_URL: https://${{ steps.wiring.outputs.domain }}
    SITE_BASE: /
```

Step 6 — Inject CNAME (DEPLOY-03):
```yaml
- name: Inject CNAME
  run: echo "${{ steps.wiring.outputs.domain }}" > dist/${{ inputs.slug }}/CNAME
```

Step 7 — Swap robots.txt (DEPLOY-04, D-06: printf is safer than sed):
```yaml
- name: Swap robots.txt to Allow
  run: printf 'User-agent: *\nAllow: /\n' > dist/${{ inputs.slug }}/robots.txt
```

Step 8 — Push to production repo (DEPLOY-08: PAT, not GITHUB_TOKEN):
```yaml
- name: Push to production gh-pages
  uses: JamesIves/github-pages-deploy-action@v4.8.0
  with:
    token: ${{ secrets.WM_PUBLISH_PAT }}
    repository: ${{ steps.wiring.outputs.prod_repo }}
    folder: dist/${{ inputs.slug }}
    branch: gh-pages
    clean: true
    single-commit: true
```

Step 9 — Update wiring.json and commit back to main (DEPLOY-05, D-08):
```yaml
- name: Update wiring.json stage 6
  run: |
    node -e "
      const fs = require('fs');
      const slug = process.env.SLUG;
      const path = 'sites/' + slug + '/wiring.json';
      const w = JSON.parse(fs.readFileSync(path, 'utf-8'));
      w.stage = 6;
      w.last_deploy = new Date().toISOString().slice(0, 10);
      fs.writeFileSync(path, JSON.stringify(w, null, 2) + '\n');
    "
    git config user.name  "github-actions[bot]"
    git config user.email "github-actions[bot]@users.noreply.github.com"
    git add sites/${{ inputs.slug }}/wiring.json
    git commit -m "chore(${{ inputs.slug }}): mark stage 6, live" || echo "No changes to commit"
    git push
  env:
    SLUG: ${{ inputs.slug }}
```

**Note on SITE_URL construction:** The domain from wiring.json is the bare domain (e.g. `www.starflight-dynamics.com`). Prepend `https://` in the env var: `SITE_URL: https://${{ steps.wiring.outputs.domain }}`.

**Note on prod_repo output:** The `node -e` inline script writes `prod_repo=pbau3r-sfdy/starflight-dynamics` to GITHUB_OUTPUT via `fs.appendFileSync`. The slash in the value is safe for GITHUB_OUTPUT key=value format.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator CLI → GitHub API | `gh workflow run` sends slug input to GitHub Actions — operator-controlled value enters workflow |
| GitHub Actions Runner → WebsiteMocker repo | Reads source files and wiring.json; pushes commit back to main via PAT |
| GitHub Actions Runner → Production repo | Pushes built output to external repo's gh-pages branch via WM_PUBLISH_PAT |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | inputs.slug used in file paths | mitigate | validate slug matches `^[a-z0-9-]+$` in the wiring validation node -e step before constructing any file paths |
| T-01-02 | Elevation of Privilege | WM_PUBLISH_PAT has repo scope on checkout + commit-back | accept | Required for cross-repo push and commit-back; Classic PAT is minimum viable scope; access restricted to org members who can trigger workflow_dispatch |
| T-01-03 | Information Disclosure | WM_PUBLISH_PAT value in workflow env | mitigate | Reference only via `${{ secrets.WM_PUBLISH_PAT }}` — never echo, log, or interpolate into shell strings; GitHub masks registered secrets in logs |
| T-01-04 | Tampering | Workflow commits back to main branch (wiring.json) | accept | Only updates stage and last_deploy fields; cannot overwrite arbitrary content; accept as required behavior per D-08 |
| T-01-05 | Denial of Service | Concurrent deploys for same slug could conflict | mitigate | concurrency group `publish-${{ inputs.slug }}` prevents parallel runs for the same site; cancel-in-progress: false queues rather than cancels |
| T-01-SC | Tampering | npm ci installs packages from lockfile in GitHub Actions runner | mitigate | npm ci uses package-lock.json exactly (no resolution drift); --no-audit suppresses advisory noise but lockfile pins remain |
</threat_model>
