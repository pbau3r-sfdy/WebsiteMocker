## Publish Invocation Model

| Option | Description | Selected |
|--------|-------------|----------|
| Local skill → triggers publish.yml | /wm-publish validates wiring.json, then runs `gh workflow run publish.yml --field slug=<slug>`. GitHub Actions builds + pushes using WM_PUBLISH_PAT. | ✓ |
| Local build → direct push from machine | /wm-publish builds locally, then uses gh CLI or git to push dist/<slug>/ directly to prod repo's gh-pages. No GitHub Actions involved. | |

**User's choice:** Local skill → triggers publish.yml (Recommended)
**Notes:** Keeps operator in Claude; GitHub Actions owns the build + push.

## DNS Handoff Guide Timing

| Option | Description | Selected |

## robots.txt Swap

| Option | Description | Selected |
|--------|-------------|----------|
| Inject in publish.yml after build | publish.yml sed/echo step overwrites dist/<slug>/robots.txt with Allow: /. Source stays Disallow: /. | ✓ |
| build-single.mjs passes env var | build-single.mjs reads ROBOTS_ALLOW=true env var and writes correct robots.txt during build. | |

**User's choice:** Inject in publish.yml after build (Recommended)
**Notes:** Simplest approach; source file stays sandbox-safe.

## Build Output Location

| Option | Description | Selected |
|--------|-------------|----------|
| dist/<slug>/ only | build-single.mjs writes only the target site to dist/<slug>/. Matches build-all.js structure. | ✓ |
| dist/ root (flattened) | build-single.mjs writes to dist/ directly. Simpler push but conflicts with sandbox deploy structure. | |

**User's choice:** dist/<slug>/ only (Recommended)
**Notes:** Consistent with how build-all.js already organizes output.

## Preflight Integration

| Option | Description | Selected |
|--------|-------------|----------|
| Always run preflight first | /wm-publish runs /wm-preflight <slug> and blocks on any FAIL items. Clear errors before GitHub Actions starts. | ✓ |
| Trust wiring.json validation only | publish.yml checks stage, domain, prod_repo and exits early. No preflight script. | |

**User's choice:** Yes — always run preflight first (Recommended)
**Notes:** Catches legal, content, and structural issues before wasting a GitHub Actions run.
