<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| contributor markdown -> Astro build | `.md` files under `sites/crestworks/src/content/` are authored by prod-repo contributors and synced in by `content-sync.yml`; their frontmatter and body cross into the build |
| collection entry id -> generated route path | `entry.id` from `getStaticPaths` becomes an output directory name |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-06 | Tampering | markdown frontmatter reaching route props | mitigate | jobsSchema / announcementsSchema Zod validation in `_core/src/content.config.ts` rejects the build on any missing or mistyped field; `type` is a closed enum, `open` is a boolean, dates go through `z.coerce.date()` |
| T-08-07 | Elevation of privilege | markdown body rendered by `render(entry)` | accept | Astro's markdown renderer permits raw HTML in `.md` bodies, so a contributor could embed `<script>`. Content authors are named `pbau3r-sfdy` org members and every synced file passes through the operator review gate in `content-sync.yml` (which never publishes) before `/wm-publish` makes it live. No sanitiser is added this phase; the risk is bounded by the trusted-author model recorded in `_templates/CONTRIBUTING.md`. |
| T-08-08 | Tampering | `entry.id` used as a route path segment | mitigate | Astro derives `entry.id` from the on-disk filename inside the globbed collection base, so it cannot escape `src/content/<collection>/`; no user-supplied string reaches the path |
| T-08-09 | Information disclosure | stub content files | mitigate | Stub copy is explicitly placeholder text with no real salary, contact, or personnel data |
| T-08-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs no packages. `npx astro build` resolves the locked `astro ^5.0.0` already present in the workspace; no new dependency enters the tree, so no package legitimacy checkpoint is required. |
</threat_model>
