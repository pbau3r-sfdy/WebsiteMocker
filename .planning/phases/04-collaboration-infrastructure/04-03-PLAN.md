        `gh-pages` build output from the index and worktree. An orphan branch is required — `main`
        must NOT share history with `gh-pages`, whose contents are regenerated and force-pushed on
        every publish.

        work on the existing branch.

    for auth; do not construct a URL containing a token.

    `mkdirSync(dirname(target), { recursive: true })` then `writeFileSync(target, content, 'utf-8')`.
    Additionally create the four content collection directories `content/news/`, `content/jobs/`,
    `content/announcements/`, `content/blog/`, each containing a `.gitkeep` file — git cannot track an
    empty directory, and a contributor using the GitHub web UI cannot create a directory without
    simultaneously creating a file in it, so without these the "Add file" flow has nowhere to land.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator workstation → production repo | the script pushes a new default branch to a live, publicly reachable repo using the operator's `gh` credentials |
| `wiring.json` → shell command strings | slug, prod_repo, name, and domain flow from a JSON file into `execSync` arguments and into rendered file contents |
| `_templates/` → contributor-visible repo contents | anything unsubstituted or wrong here becomes public documentation on a live repo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-13 | Elevation of privilege | `execSync` argument construction | mitigate | `slug` is validated against `^[a-z0-9-]+$` and `prod_repo` against `^[A-Za-z0-9._-]+/[A-Za-z0-9._-]+$` before either is interpolated into any `gh` or `git` command string; both guards run in the Task 1 preflight, before any command is built |
| T-04-14 | Destruction of data | `gh-pages` branch on the production repo | mitigate | The script only ever checks out and pushes `main`. `git rm -rf .` runs exclusively inside a detached orphan worktree in a temp directory and is never followed by a push to `gh-pages`. Asserted by a grep gate: no push targeting `gh-pages` exists in the file |
| T-04-15 | Information disclosure | git remote URL in the temp clone | mitigate | The clone URL is plain `https://github.com/<owner>/<repo>.git` with no embedded token; authentication comes from the `gh` credential helper, so no credential is written into the temp clone's git config or into any process argument list visible via `ps` |
| T-04-16 | Tampering | unsubstituted `{{TOKEN}}` reaching a public repo | mitigate | `renderTemplates()` asserts no rendered content contains `{{` and fails the run naming the offending file, so a template that Plan 02 later extends cannot silently publish a raw placeholder or the string `undefined` to a live contributor-facing repo |
| T-04-17 | Repudiation | commits authored on the production repo | accept | Commits are attributed to the operator's local git identity (or `github-actions[bot]` when unset). Signed commits are explicitly out of scope for this milestone — REQUIREMENTS.md records that signed-commit branch protection is permanently incompatible with GitHub web UI editing |
| T-04-18 | Elevation of privilege | premature `content-ci.yml` on a non-live site | mitigate | The `wiring.stage >= 6` gate drops `content-ci.yml` from the install set for any site that is not live, so a contributor push cannot publish an unfinished site. All four sites are stage 6 at plan time, so the gate is currently permissive — it is a guard for future sites, not a scope reduction |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs. The recursive directory walk uses `fs.readdirSync(..., { withFileTypes: true })` rather than adding a glob dependency, keeping the phase's new-dependency count at zero npm packages |
</threat_model>
