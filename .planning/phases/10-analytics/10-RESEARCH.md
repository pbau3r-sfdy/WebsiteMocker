## Summary

The existing `_scripts/plausible.mjs` (61 lines) is the only moving part: it reads `wiring.json` at `astro:config:setup`, returns early unless `analytics.service==='plausible' && status==='configured'`, picks sandbox by `config.base.startsWith('/WebsiteMocker')`, and injects a legacy `data-domain` loader via `injectScript('head-inline', ...)`. Phase 10 extends this one file, extracts the sandbox test to `_scripts/lib/env.mjs`, and adds an event/sanitise layer. No new npm dependency is needed (Node built-ins only; Astro stays 5.18.x). The current tracker (Oct 2025 "per-site script") takes all behaviour in `plausible.init({...})`; the options relevant here are `outboundLinks`, `fileDownloads` (bool or `{fileExtensions:[...]}`), `formSubmissions`, `customProperties` (object or function), `transformRequest`, `autoCapturePageviews`, `hashBasedRouting`, `captureOnLocalhost`, `endpoint`.

The most important finding for ANLY-05: the tracker sets `payload.u = location.href` (fragment included, no stripping in the client), props are attached to all event types including file-download and outbound events, and `transformRequest(payload)` runs on every payload and can mutate it or return a falsy value to drop the event. So sanitising must be implemented in `transformRequest`, covering both `u` and the props (the `url` prop of Download / Outbound Link events can carry secrets such as a future `/d/<id>/file.pdf`). The sanitiser must be a small, deterministic pure function that is shared between the emitted browser code and the verify harness (test it in Node by evaluating the same string).

Reskin-2 specifics: it has no `analytics` block, no `404.astro` (404 event needs a new page), and its contact form is a plain cross-origin `<form action="https://api.web3forms.com/submit">`. A key design wrinkle is that a `pa-` script ID carries no domain, so ANLY-03 cannot compare "domain in the tag" to the build kind; it must compare wiring declarations (which identity is declared for which build kind) and refuse the dangerous combination (sandbox build + production identity) unless the loud D-02 opt-in is set.

**Primary recommendation:** Extend `plausible.mjs` in place (scriptId path + legacy fallback), move `isSandbox`/`SANDBOX_DOMAIN` to `_scripts/lib/env.mjs`, generate the init options and a shared sanitising `transformRequest` from wiring.json, throw (fail the build) on identity/build-kind mismatch, and test everything with a fixture-based `verify-phase-10.sh` that builds a tiny Astro fixture or, cheaper, calls the integration hook directly with a stub `injectScript`.

### Pattern 1: `isSandbox` helper (ANLY-01)
**What:** `export const isSandbox = (base) => typeof base === 'string' && base.startsWith('/WebsiteMocker')`; accept either the config object or the string. Add `SANDBOX_DOMAIN` here too and re-export from `plausible.mjs` for back-compat. ### Pattern 2: Identity resolution and the ANLY-03 assertion
A `pa-` script ID encodes no domain, so assert declarations. Proposed `wiring.json` schema (additive to the existing keys `service,status,domain,sandbox,host`):
```json
"analytics": {
  "service": "plausible", "status": "configured",
  "scriptId": "pa-h84OFEpVhPIHGnzKLeThr",
  "domain": "starflight-dynamics.com",
  "sandboxScriptId": null,
  "sandboxUsesProdId": true,
  "events": { "outboundLinks": true, "fileDownloads": true, "formSubmissions": true, "notFound": true },
  "sanitise": true,
  "props": false
}
```
Resolution matrix (the verify harness must cover every row):

| Build kind | scriptId | sandboxScriptId | sandboxUsesProdId | Result |
|---|---|---|---|---|
| prod | set | - | - | emit prod `pa-` tag |
| prod | unset | - | - | legacy tag, `data-domain` = `analytics.domain` or `wiring.domain` minus `www.`; throw if empty |
| prod | any | - | - | THROW if resolved domain equals `SANDBOX_DOMAIN`, or if `analytics.domain` is set to a `github.io` host |
| sandbox | set | unset | false/unset | emit nothing, info log (protective default, D-02) |
| sandbox | set | set | - | emit sandbox `pa-` tag |
| sandbox | set | unset | true | emit prod tag + loud `logger.warn` (every build) |
| sandbox | unset (legacy) | - | - | legacy tag to `SANDBOX_DOMAIN` unless `sandbox:false` (existing behaviour; the default for legacy sites is unchanged) |
| any | `sandbox:false` and sandbox build | - | - | emit nothing; `sandboxUsesProdId` must not override an explicit `false` (throw on contradictory config) |

Also assert `scriptId` matches `^pa-[A-Za-z0-9_-]+$` (also accept bare ID and prepend `pa-`? Recommend: store the full `pa-...` token; reject anything else, so a pasted URL cannot inject markup). Always emit via `JSON.stringify` (existing pattern).
Throw with `throw new Error(...)` inside the hook; Astro fails the build on a thrown integration hook [ASSUMED from Astro behaviour; verify in the harness by asserting non-zero exit]. Note on the contradiction with ANLY-02 "legacy fallback": keep legacy sandbox behaviour for sites without `scriptId` only; sites with `scriptId` get the stricter D-02 default. Flag in plan summary.

### Pattern 3: Sanitised tracking mode (ANLY-05)
Facts: tracker `payload.u = location.href` (fragment present); `transformRequest(payload)` may mutate or return falsy to drop; props `payload.p` are present on all event types [CITED: github.com/plausible/analytics tracker/src/track.js; plausible.io/docs/custom-locations]. Therefore:
- Always (not only in sanitised mode): `hashBasedRouting` is never set. Never emit it.
- Sanitised `transformRequest` (generated, one shared source string): rebuild `u` from `location.origin + sanitisedPath` (drop query and fragment entirely unless a whitelist is configured), replace `/d/<32hex>/` and any 32+ hex or long base64url segment with `/_ID_/`-style placeholder, and run the same replacement over every string value in `p` (handle `p` as object or JSON string defensively [ASSUMED payload shape; confirm with a console test in the debug session]). Optionally also scrub `r` (referrer) to origin only.
- Exclusion variant: return `null` for payloads whose path matches `analytics.exclude` globs (documented to drop the event [CITED: tracker source]). Drops in Phase 11 can use either: sanitised rewrite to `/d/_ID_/` (preferred, keeps counts).
- Sanitise is on by default for configured sites (cheap, privacy-protective). Keep the function ES5-ish, no regex lookbehind, to run in any browser.
- The sanitiser source is one JS string exported from `lib/plausible-snippet.mjs`; the harness does `new Function('return '+SRC)()` in Node and feeds payload fixtures including `#fragment`, `?token=`, `/d/<hex>/x.pdf`.

## Common Pitfalls

### Pitfall 1: Sandbox pollutes the production Plausible site (D-02 opt-in)
**What goes wrong:** with `sandboxUsesProdId`, github.io pageviews land in the `starflight-dynamics.com` site with paths `/WebsiteMocker/sfdy-alt-clean-reskin-2/...`, inflating real stats; the trial's page-view allowance is also consumed.
**How to avoid:** opt-in only on reskin-2; `logger.warn` every build; add `customProperties`/path filter note to the checklist (filter `Page contains /WebsiteMocker`); verify harness asserts the warning text; Phase 12 task "set `sandboxUsesProdId` false/remove" recorded in the plan and in `PARKED`/Phase 12 notes. Plausible has a Shields -> Hostname allowlist option to reject non-matching hostnames [ASSUMED feature; confirm in Settings]; once set, sandbox debug events would be rejected, so only enable it at cutover.

### Pitfall 2: Event names do not match goals
**What goes wrong:** requirement text says `Download`/`Form`; tracker emits its own names; goals never show. **How to avoid:** observe real network payloads in the debug session, write the contract from observation, create goals from the contract.

### Pitfall 3: 404 on GitHub Pages sandbox
**What goes wrong:** Pages serves `404.html` only from the site root; under `/WebsiteMocker/<slug>/` an unknown URL shows the dashboard's 404 (or none), not the site's. **How to avoid:** test the 404 event by opening `<base>/404.html` directly; in production (base `/`, custom domain) it works naturally. Reskin-2 has no `404.astro` today: create it with the site layout, noindex, and the inline event call. The queue stub makes the call safe before the script loads. Do not call `plausible('404')` on any page other than the real 404 page.

### Pitfall 4: Contact form submission event
**What goes wrong:** web3forms posts cross-origin with a normal submit; the page unloads, the form event may be lost or arrive as an outbound-like navigation. **How to avoid:** accept best-effort `formSubmissions`; if the site later uses JS fetch submit, fire `plausible('Form')` manually. Note it in the debug checklist rather than over-engineer.

### Pitfall 5: `astro dev` and localhost
Existing code returns when `command !== 'build'`; keep that. `captureOnLocalhost` stays false; `astro preview` of a production build would still send events from localhost? The tracker ignores localhost by default [CITED: init option default false], so local previews are safe.

### Pitfall 6: Two-config duplication
`_core/astro.config.mjs` and each site config list `plausible()` individually. Reskin-2 already has it. Verify `_core` still lists it; no other site is touched (D-05). The harness should check that sites with `status: skipped` emit nothing.

### Pitfall 7: Staging and working tree
The tree has many unrelated uncommitted files (D-07). Every commit uses explicit paths; reskin-2's `privacy-policy.astro` and `index.astro` may carry 11.1 edits: do not touch them in Phase 10 plans except wiring.json, `404.astro`, and docs.

### Pitfall 8: Trial-period reality
The Plausible dashboard says "could not detect Plausible" until the first pageview arrives from a deployed page. The debug session needs: build with the opt-in, push (operator decides), load the sandbox URL, watch Network for `plausible.io/api/event` 202, then check the dashboard. Nothing appears from a local `astro preview` (localhost ignored).

  p.u=clean(p.u);                       // already absolute; origin kept
  if(p.r){p.r=String(p.r).split('#')[0].split('?')[0];}
  var pr=p.p; if(typeof pr==='string'){try{pr=JSON.parse(pr)}catch(e){}}
  if(pr&&typeof pr==='object'){for(var k in pr){if(typeof pr[k]==='string')pr[k]=clean(pr[k]);}}
  p.p=(typeof p.p==='string')?JSON.stringify(pr):pr;
  return p;
}
