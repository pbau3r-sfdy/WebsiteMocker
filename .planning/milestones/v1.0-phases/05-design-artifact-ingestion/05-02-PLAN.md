  <action>
    Add section mode to `_scripts/ingest-artifact.mjs`. Locate the modeArg routing block (where `modeArg === 'full'` is handled) and add the `modeArg === 'section'` branch beside it.

    SECTION MODE VALIDATION: If modeArg==='section' but sectionArg is null, call fail('--mode section requires --section <name>').

    HELPER — writeSectionMode(slug, sectionName, sections, cssText, siteDir, date): Implements INGEST-03.
    1. Find the matching section entry: search sections array for an entry where entry.id===sectionName OR entry.classes[0]===sectionName OR entry.name.toLowerCase()===sectionName.toLowerCase(). If not found: fail('Section "'+sectionName+'" not found in artifact. Available: ' + sections.map(s=>s.name).join(', ')).
    2. Re-parse the artifact HTML from disk (readFileSync artifactPath). Navigate fromHtml tree to body. Find the matching element node by tagName+id+class matching the found section entry.
    3. sectionHtml = toHtml(sectionNode).
    4. scopedCSS = extractScopedCSS(cssText, section.classes[0], section.id). Exclude :root/body/html/* rules.
    5. Convert linked stylesheets: convertLinkedStylesheets(sectionHtml, join(ROOT,'_captures',slug,'raw')).
    6. Handle base64 images: same decode logic as full-site mode, writing to join(siteDir,'public','images',slug).
    7. sectionHtml = rewriteLocalPaths(sectionHtml, slug).
    8. componentName = toPascalCase(sectionName).
    9. component = toAstroComponent(sectionHtml, scopedCSS, componentName, date).
    10. componentPath = join(siteDir,'src','components',componentName+'.astro').
    11. If !DRY_RUN: mkdirSync(join(siteDir,'src','components'),{recursive:true}); writeFileSync(componentPath, component, 'utf-8'); ok('wrote '+componentName+'.astro').
    12. Else: dry('would write '+componentName+'.astro').
    13. Print the manual import instruction to stdout (always, even in dry run):
        log('\nComponent staged. To use it, add to your page:');
        log('  import '+componentName+' from \'../components/'+componentName+'.astro\';');
        log('  <'+componentName+' />');
        log('No existing pages were modified.');

    SECTION MODE ROUTING: In the modeArg routing block, add: if modeArg==='section', resolve and validate artifactPath, read htmlString, call extractSections and extractStyleCSS, compute date, call writeSectionMode(slug, sectionArg, sections, cssText, siteDir, date).

    CRITICAL CONSTRAINT: The writeSectionMode function and the section mode routing block must NEVER call writeFileSync on any path inside `sites/<slug>/src/pages/`. The only writeFileSync calls allowed in section mode are to `sites/<slug>/src/components/` and `sites/<slug>/public/images/<slug>/`.
  </action>

    STEP 1 — Collect inputs:
    Ask the operator for three things: (a) Target slug — must exist in sites/; validate with `ls sites/<slug>/wiring.json`. (b) Artifact — operator pastes HTML content directly in the chat, or provides a local file path. (c) Mode — `full` (all sections → full site rebuild) or `section` (one named section → new component only, existing pages untouched).

    STEP 2 — Stage the artifact:
    Write the pasted HTML (or copy from the provided path) to `_captures/<slug>/raw/artifact.html`. Create `_captures/<slug>/raw/` if it does not exist. Include a bash block showing: `mkdir -p _captures/<slug>/raw/` and the write action.

    STEP 3 — Analyze (before any writes):
    Run `node _scripts/ingest-artifact.mjs <slug> --analyze` and read the JSON output. Present to the operator: section manifest (names, tags, ids), CSS collision report (conflicts between artifact vars and Layout.astro vars), and asset inventory (image count, base64 image count, Google Fonts links).

    STEP 4 — Confirm CSS collision report (MANDATORY GATE):
    Present the full collision report. Even if there are zero conflicts, ask: "Collision scan complete — N conflicts found. Proceed with ingest? (y/N)". If conflicts exist, list each conflict by name with existing value vs artifact value. Do NOT proceed to Step 5 until the operator explicitly types `y`. This step is mandatory for every ingest, zero-conflict or not.

    STEP 5 — Run ingest:
    For full mode: `node _scripts/ingest-artifact.mjs <slug> --mode full`. For section mode: `node _scripts/ingest-artifact.mjs <slug> --mode section --section <name>`. Include both commands in separate bash blocks with a note explaining the difference. Mention that `--dry-run` can be appended to preview without writing.

    STEP 6 — Surface brand candidates:
    Present the extracted CSS custom properties from the artifact as an informational report. Format each as: `  --var-name: value  (currently: existing-value — CONFLICT, keep existing?)` or `  --var-name: value  (new — add to Layout.astro :root manually?)`. Explicitly state: "These are informational only — they are NOT written to `wiring.json`. To adopt any token values, update `sites/<slug>/src/layouts/Layout.astro` `:root {}` manually."

    STEP 7 — Verify and report:
    Run `node _scripts/build-all.js <slug>`. Report: number of components created, assets copied, collisions resolved or skipped, and what to customise next (brand tokens, hero content, nav links). Include bash block for the build command.

    NOTES SECTION (## Notes, after the --- divider):
    Write at least 6 bullet points covering:
    1. `_core/` is never touched — ingest only writes to `sites/<slug>/src/components/` and `sites/<slug>/src/pages/` (full mode only)
    2. Section mode is write-only — it writes a new component but never modifies existing pages; operator must add the import manually per the printed instruction
    3. Nav.astro and Footer.astro overwrite protection — if already customised (differs from _core/ template), the script skips the overwrite and logs a warning; review the artifact Nav/Footer manually
    4. Google Fonts `<link>` tags are not converted to `<style>` blocks — they are printed as instructions to add to Layout.astro `<head>`
    5. BASE_URL routing — all local `src="/..."` and `href="/..."` paths are rewritten to `{b}/...` during extraction; the sandbox and production builds both work correctly
    6. If build fails after ingest, check: (a) missing import in index.astro, (b) malformed template literal from path rewriting, (c) unclosed Astro frontmatter — list the error and suggest manual fixups
  </action>
